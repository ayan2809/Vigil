# Glossary

Domain terms, internal concepts, and names a future session needs to parse this codebase correctly.

| Term | Meaning |
|---|---|
| **Satan** | Current product name (renamed from "Vigil" — see [DECISIONS.md](DECISIONS.md)). Also the Python package name (`backend/satan/`), the FastAPI app title, the logger namespace prefix (`satan.backend`, `satan.tracker`, `satan.menubar`), and the LaunchAgent label prefix (`com.satan.*`). |
| **Vigil** | The product's previous name. Still present in: the working directory path, `dashboard/package.json`'s `name` field, legacy `VIGIL_*` environment variable fallbacks, `data/vigil.db` migration source, and `vigilServerUrl` browser storage key fallback. Not a separate/related project — same codebase, prior name. |
| **Intent vs. Reality** | The dashboard's organizing UX philosophy (`memory.md` §6.4): the left column ("Intent") shows the task queue and daily core values/rules the user set for themself; the right column ("Reality") shows what activity was actually tracked. Not a code identifier — a design concept referenced in comments/docs. |
| **TrackingLogs** | The single event-sourced table storing every raw activity event (app switches, tab changes, Pomodoro completions). See [DATA_FLOW.md](DATA_FLOW.md). |
| **`local_date`** | A `YYYY-MM-DD` string column on `TrackingLogs`, computed from the local timezone at event-receipt time (not UTC). Used to bucket events by "day" for aggregation. |
| **`occurred_at`** | Offset-aware ISO-8601 timestamp (e.g. `2026-07-24T15:30:00+05:30`) recorded when the backend receives an event — always server local time, never client-supplied. |
| **Active time / laptop time** | The aggregate duration a Mac was in active use, computed from gaps between consecutive `TrackingLogs` events (see the `LEAD() OVER (...)` pattern). Used interchangeably in code/docs as "laptop time" (dashboard label) and "active time" (SQL/route naming). |
| **Focus time** | Total duration accumulated from completed Pomodoro work sessions (`event_type = 'pomodoro_completed'` rows), as distinct from general "active time." Not derived from the window-function gap calculation — it's summed directly from each event's `metadata_json.duration_seconds`. |
| **Pomodoro** | A timed focus-then-break work interval. Default 25 min work / 5 min break (`DEFAULT_WORK_SECONDS` / `DEFAULT_BREAK_SECONDS` in `backend/satan/models.py`), user-configurable via `user_settings.pomodoro_duration_minutes`. |
| **`TimerState`** | The in-memory dataclass (`backend/satan/models.py`) representing the live Pomodoro state: `status` (`idle`/`running`/`paused`), `phase` (`work`/`break`), `remaining_seconds`, `task_id`, etc. One global instance per backend process (`timer_state` in `backend/satan/timer.py`). |
| **`PersistentTimerState`** | The SQLite table (singleton row, `id=1`) that shadows `TimerState` for crash/restart recovery. Written on every state transition; read only at server startup. |
| **Outbox pattern** | The `email_outbox` table + two decoupled jobs (generate, then separately send) used for nightly reflection emails, so that generation and delivery can fail/retry independently. See [DATA_FLOW.md](DATA_FLOW.md#5-nightly-reflection-email-flow-outbox-pattern). |
| **Nightly reflection** | The single daily summary email sent near the user's configured sleep time, summarizing focus time, laptop time, and top-3 apps used that day, in a format intended to be glanceable on an Apple Watch. |
| **WatchOS-formatted / watch-friendly** | Refers to the terse formatting used for the nightly email subject/body (e.g. `4h 15m` instead of `4 hours, 15 minutes`; medal emoji instead of ranked list) — optimized for a small Apple Watch notification glance, not for a full-screen email client. |
| **Sleep time** | A user-configured `HH:MM` setting (`user_settings.sleep_time`, default `23:00`) representing when the user intends to go to bed. Used only to derive the nightly reflection job's trigger time (`sleep_time - 15 minutes`) — not connected to macOS sleep/wake events despite the similar name. |
| **Trigger time** | The computed `(hour, minute)` at which the nightly reflection generator cron job actually fires — always exactly 15 minutes before `sleep_time` (`parse_sleep_time_to_trigger` in `backend/satan/scheduler.py`). |
| **Misfire grace time** | An APScheduler concept: how long after a job's scheduled fire time it's still allowed to run if the process wasn't alive at that exact moment (set to 3600s/1hr here) rather than being skipped as "missed." Key to sleep-resilience — see [DECISIONS.md](DECISIONS.md#4-outbox-pattern-for-email-delivery-decoupled-from-generation). |
| **Backfill** | The startup routine (`check_and_backfill_missing_reflections`) that scans the past 7 days for any date with recorded activity but no `email_outbox` row, and generates the missing one. Distinct from the nightly cron job — this runs once per server startup, not on a schedule. |
| **Monthly goal(s)** | User-set free-text focus goal(s) for the current month, displayed in the dashboard's `MonthlyGoalBanner`. Stored as both a legacy singular `monthly_goal` string and a current `monthly_goals` JSON array column — see [DECISIONS.md](DECISIONS.md#6-dual-monthly-goal-fields-monthly_goal-singular--monthly_goals-array). |
| **Core values / Daily rules** | User-set list of personal principles/ground rules, stored as a JSON array in `user_settings.core_values`, rendered by the `DailyValues` component in the dashboard's "Intent" column. |
| **Source** (`TrackingLogs.source`) | Either `'app'` (from `mac_tracker.py`, a macOS foreground application) or `'browser'` (from `background.js`, a browser tab). Determines which fields are populated (e.g. only `browser` events have a meaningful `domain`). |
| **Event type** (`event_type`) | A free-text field identifying what kind of event occurred: `frontmost_application_changed` (mac tracker), `tab_activated` / `tab_updated` / `window_focused` / `history_state_updated` (browser extension), `pomodoro_completed` (backend-generated), or the model default `active_change` (unused by current clients but accepted by the schema). |
| **`get_db()`** | The FastAPI dependency (`backend/satan/db.py`) yielding a request-scoped `aiosqlite.Connection` with WAL mode, busy timeout, and foreign keys pre-configured. The sole sanctioned way to touch the database. |
| **WAL mode** | SQLite's Write-Ahead Logging journal mode, enabled on every connection (`PRAGMA journal_mode = WAL`) to allow concurrent reads while a write is in progress — important given multiple independent processes (backend, tests) may open the same DB file. |
| **`.agents/AGENTS.md`** | The repository's own rulebook for AI coding agents (not a generic README) — mandates memory.md upkeep, zero-`print()`, non-blocking I/O, the zero-polling tracking model, parameterized SQL, and mandatory test runs. Read before making backend changes. |
| **`memory.md`** | A living, actively-maintained architecture/schema/API blueprint at the repo root, distinct from this `docs/` tree — treat it as the fast/current reference and `docs/` as the deeper, narrative reference. Repo convention requires updating it alongside any schema/route/env change. |
| **Focus Load** | Apple-Training-Load-style metric: recent focus volume (acute, last 7 days incl. today) versus the conditioned baseline (chronic, last 28 days). Served by `GET /focus-load`; computed in `backend/satan/focus_load.py`. |
| **FLU (Focus Load Unit)** | One day's load: `focus_minutes × (0.5 + 0.5 × density)`, so focused-and-dense days count up to 2x an unfocused day of the same length. |
| **Density** | A day's focus time divided by laptop time, clamped to 0–1. |
| **Load classification** | Δ% = (acute − chronic) / chronic, bucketed as `well_below` (< −20), `below` (< −5), `steady` (≤ +10), `above` (≤ +30), `well_above`. |
| **`DailyActivityRollup`** | Table of finalized per-day laptop/focus seconds, written before the 30-day raw-log purge so Focus Load history outlives `TrackingLogs`. |
| **`system_sleep`** | Event emitted by `mac_tracker.py` when the lid closes or the display sleeps. Stops time accruing, and auto-pauses a running Pomodoro (`pause_reason = "system_sleep"`). Not related to the user's `sleep_time` setting. |
